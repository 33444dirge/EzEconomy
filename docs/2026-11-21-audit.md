# EzEconomy 优化、生命周期与 Folia 检查

检查基线：`8252042`，工作分支 `jiujiu`。范围包含 Bukkit 主插件、消费账本、Redis、PlaceholderAPI、Bungee 通信与代理、Velocity 代理。保留对外经济接口、账本类名与持久化表结构。

## 已修复的问题

| 范围 | 原问题 | 修复 |
| --- | --- | --- |
| 玩家锁 | 静态 UUID 锁表永久保留历史账户；错误释放会提前消费 token | 弱引用锁保持并发锁身份，引用队列清理；token 持有强引用并校验账户、持锁线程 |
| YML 锁与 Vault 锁 | 每个账户、银行、货币分别创建永久锁对象 | 固定数量锁条带，避免随历史账户无限增加 |
| 本地缓存 | 过期键不清理、无容量上限 | 容量限制、访问顺序淘汰、每分钟清理；保留短暂过期快照供异步刷新使用 |
| 缓存后端 | 更换策略不关闭旧 Redis / JDBC / 代理连接；启动时重复初始化策略 | 统一 `CacheManager` 资源所有权；关闭旧后端；移除锁组件中的重复缓存初始化 |
| 玩家索引 | 静态缓存可能持有在线 `Player` 及其关联对象 | 缓存只保存 UUID、名字；停用和监听器停止时清理 |
| 插件重载 | 旧余额线程池、银行计息任务、指标实例、Vault 服务及占位符实例可能重复保留 | 组件按依赖顺序启动、逆序停止；部分启动失败也回滚；重载先完整停止旧组件 |
| 独立资源 | 检查 JAR 资源存在性时未关闭流；外部锁类加载器过早关闭 | 检查流自动关闭；扩展类加载器保留到对应组件停用 |
| 付款流程 | 可变共享 Flow；聊天流程无明确过期；延迟任务持有 Player；过期确认可被取出 | 不可变快照、过期检查、UUID 清理、退出清理、停用清空；保留选定货币和收款人名字 |
| Folia 玩家操作 | 异步聊天确认 GUI、延迟通知、跨区收款消息可能使用全局线程 | 共用 `runForPlayer` 实体调度入口；离线或退休时清理；库存点击后的切换延迟一个实体 tick |
| Folia 事件 | tick 线程同步等待其他 tick；取消事件派发失败后仍可能付款 | Folia tick 线程直接派发事件；派发失败取消可取消事件 |
| IO 生命周期 | common pool 工作无法随插件管理；银行计息、玩家入服数据、GUI 查询阻塞 tick | 插件管理的有界 IO 工作队列；停止接收后排空；GUI 展示返回玩家线程；计息避免任务重叠 |
| GUI 安全 | 底部背包物品可误触菜单；拖动物品未拦截；确认菜单可能被菜单标题分支抢先匹配 | 仅处理顶层槽、拦截拖入、调整分支；确认/取消支持明确动作标记 |
| 群发付款 | 后续货币转换失败时退款覆盖已付金额 | 全部转换先校验；入账失败仅退未付款部分，退款失败留下核对日志 |
| SQLite 余额 | 缓存余额再次叠加 pending；待写扣款绕过 SQL 条件 | 入账缓存只加本次金额；扣款先同步结清待写金额，再执行 SQL 条件扣款 |
| 后台写入 | 只处理一批后丢弃其余待写键的唤醒，队列满时也可能永久滞留 | 每轮重新纳入 pending 键；SQLite 单键刷新与后台批次串行，失败重新保留记录 |
| 账本接入 | SQLite 关闭余额缓存后仍启动后台写队列，导致 attach 拒绝 | 关闭余额缓存时同步关闭该队列；MySQL 重连更新账本连接而保留绑定 |
| 可选模块 | PAPI 长期持有被替换的缓存；排行重复提交刷新；代理 transport 缺少关闭入口 | 动态获取缓存、合并同键刷新；显式注销扩展、消息通道、等待 future 与 Velocity 定时任务 |

## 简化和清理

- 删除重复的 `ShutdownComponent`，Vault 服务由 EconomyComponent 负责释放。
- 删除余额专用 `BalanceScheduler`，共用平台玩家调度入口。
- `/eco gui` 复用 BalanceAction，删除重复数据库遍历。
- 三个本地后端占位实现复用 LocalCacheProvider，保留公开类名。
- 删除主插件中已迁入 ConfigComponent 的旧私有常量；修复默认 GUI YAML 重复 `actions` 键，启用项改为各动作下的 `enabled`。
- 付款成功的详细数据库日志受 `debug` 控制，减少每次付款的日志 IO。

## 验证边界

回归覆盖真实 SQLite、H2 MySQL 模式、并发锁身份、缓存淘汰、队列满载、连续三次重载、过期确认、异步余额回复、Folia 线程调度和事件失败取消、余额重复累计、群发付款转换失败。执行 Maven 全模块测试和打包，最终结果以本文件的验证记录为准。

MockBukkit 与 H2 不代替真实 Folia、正式 MySQL、Redis、Bungee/Velocity 网络或客户端验收。本次没有正式服堆转储、JFR 持续采样和长时间在线压力曲线，因此不能据此保证不存在任何运行时内存泄漏，也不报告未经测量的性能提升百分比。

同步 Vault/StorageProvider API 仍按现有同步契约返回结果；管理员数据库命令、部分银行/付款路径及同步占位符调用仍可能执行数据库 IO。已修复的线程问题不等于所有第三方事件监听器、第三方 Vault 调用和服务器实现都兼容。后续如要彻底消除这类 IO，应在调用方提供异步接口和明确的成功回执，不能仅把全部 Player 操作搬到工作线程。

`/ezeconomy reload` 现在按组件生命周期重建运行状态，会重新初始化存储、缓存和账本后端；依赖外部岛屿插件 attach 的消费排行应完整重启配套插件，避免继续使用旧绑定。替换 JAR 使用完整停服重启。
